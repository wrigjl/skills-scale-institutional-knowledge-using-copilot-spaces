---

## Summary of OctoAcme's Project Management Approach

OctoAcme follows an **iterative, data-informed delivery** model built around a few core principles:

- **Clear role ownership and documented cadence** — every phase has defined owners and regular touchpoints so work stays visible and accountable.
- **Key phases** — projects move through *initiation*, *planning*, *execution*, *release*, and *continuous improvement*, each with lightweight artifacts and explicit entry/exit criteria.
- **Small, testable increments** — work is broken into deliverables that can be independently validated, reducing risk and enabling faster feedback.
- **Clear acceptance criteria** — every piece of work carries explicit criteria so teams and stakeholders share a common definition of done.
- **Transparent communication** — risks, blockers, and status are surfaced early and often through structured communication rhythms.

## Contributing & Updating Process Documentation

Process docs are living documents — keeping them accurate is a shared responsibility.

1. **Identify the change.** Open a GitHub Issue describing what needs to be updated and why. Reference the affected document(s) using the *Add Content to Project Management Process Docs* issue template.
2. **Create a branch.** Branch off `main` using a descriptive name such as `docs/update-planning-process`.
3. **Make your edits.** Update the relevant Markdown file(s) in the `docs/` folder. Keep changes focused; one logical change per pull request.
4. **Update this README** if you add, remove, or rename a document so the index stays accurate.
5. **Open a Pull Request.** Link the PR to the originating issue and request a review from a process owner before merging.
6. **Merge and close.** Once approved, merge to `main` and close the associated issue.

For questions about the process, open a GitHub Discussion or reach out to the team's project management guild.
